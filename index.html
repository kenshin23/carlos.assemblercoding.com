Método

Sobre trabajar con agentes de IA

Escribo la mayor parte del código con agentes, y no lo escondo. Lo que separa una base de código asistida por IA que se sostiene de una que se desmorona no es el modelo: es lo que uno pone alrededor.

  • Convenciones escritas donde el agente las lee. Un archivo de reglas que empieza por la restricción que produce fallas silenciosas, no por preferencias de estilo.
  • Especificación antes de generación. Los documentos de diseño se revisan contra los modelos que ya existen; algunos terminan diciendo "todavía no construyas esto".
  • Límites arquitectónicos exigidos. Una capa de servicios evita que el código generado se desparrame a la capa equivocada.
  • Las pruebas como criterio de aceptación. Generar es barato; la suite es lo que hace seguro aceptar.
  • Una pasada adversarial sobre el trabajo propio. El código que uno no tecleó merece más escrutinio, no menos. Por eso audito lo que construyo.

Method

On working with AI agents

I write most of my code with agents, and I don't hide it. What separates an AI-assisted codebase that holds together from one that collapses isn't the model — it's what you put around it.

  • Conventions written where the agent will read them. A rules file that opens with the constraint which causes silent failure, not with style preferences.
  • Specification before generation. Design docs reviewed against the models that already exist; some of them end up saying "don't build this yet".
  • Architectural boundaries, enforced. A service layer keeps generated code from sprawling into the wrong layer.
  • Tests as the acceptance gate. Generating is cheap; the suite is what makes it safe to accept.
  • An adversarial pass over my own work. Code you didn't type deserves more scrutiny, not less. So I audit what I build.
